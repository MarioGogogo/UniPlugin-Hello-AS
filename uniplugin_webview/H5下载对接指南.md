# H5 文件下载对接指南（UniWebView 原生下载）

> 适用对象：在 App 内置 WebView（UniWebView 插件）中打开的 H5 页面开发者
> 更新时间：2026-11-09
> 适用插件版本：uniplugin_webview（含 H5 下载支持，需 App 端重新打包基座）

---

## 一、背景

你们的 H5 页面（如账单页 `bill.html`）运行在 App 的原生 WebView 里。Android WebView 有两个已知限制：

1. **不支持 `blob:` URL 下载和 `<a download>` 属性**（Chromium 限制）——PC 浏览器里好使的 `fetch → blob → a.click()` 方案，在 App WebView 里点了没反应
2. 普通 `<a href="xxx.html">` 直链会被 WebView **渲染成页面**而不是下载

为此 App 端插件提供了**原生下载能力**，H5 只需按本文对接。文件最终保存到手机**系统下载文件夹**（`/storage/emulated/0/Download/`），用户在"文件管理"里可直接看到，**无需用户授予任何权限**。

---

## 二、前置条件

- App 已打包含下载支持的新版 WebView 插件（旧基座不具备下载能力，需 App 同学重新出包）
- 页面通过 UniWebView 组件打开（此时 `window.UniWebView` 桥接对象才存在）

---

## 三、判断运行环境

```javascript
function isInApp() {
  return !!(window.UniWebView && typeof window.UniWebView.postMessage === 'function');
}
```

- `true`：App 内 WebView，走原生下载
- `false`：普通浏览器（PC / 手机浏览器），走浏览器自带下载

**建议 H5 同时实现两条路径**，同一份代码在 App 和浏览器里都能正常下载（见第七节完整示例）。

---

## 四、推荐方案：直接 URL 下载（一行代码）

把文件的**真实 URL**（后端/OSS 地址）发给 App，原生用系统 DownloadManager 下载，无视 Content-Disposition，HTML 文件也能下：

```javascript
window.UniWebView.postMessage(JSON.stringify({
  type: 'download',
  data: {
    url: 'https://foxhisfiles.oss-cn-hangzhou.aliyuncs.com/9999999/SLIM/bill.html',
    filename: '账单.html'   // 可选，不传时按 URL 末段命名
  }
}))
```

要点：

| 项目 | 说明 |
|------|------|
| `url` | 必填，必须以 `http://` 或 `https://` 开头（OSS 签名地址同样适用） |
| `filename` | 可选，期望的保存文件名；不传则取 URL 最后一段（如 `bill.html`） |
| 下载结果 | H5 不直接收回调，由 App 端转发到 `window.onDownloadResult`（见第六节）；App 端同时有 Toast 提示 |

**这是最稳定的方式，新页面一律推荐用这个。**

## 五、兼容方案：现有 blob 下载代码（零改动）

如果页面已有 `fetch(OSS地址) → blob → <a download> → a.click()` 的代码，**可以一行不改**——App 插件会在页面加载完成后自动注入拦截脚本：

- 拦截 `<a href="blob:...">` 的点击（包括 JS 程序化 `a.click()`）
- 自动把 blob 转成 base64 交给 App 保存到系统下载文件夹
- **文件名取 `<a>` 标签的 `download` 属性**，请确保设置了它：

```javascript
// 现有代码保持不变，确保 download 属性有值即可
const a = document.createElement('a');
a.href = URL.createObjectURL(blob);
a.download = '账单.html';   // ← App 按这个名字保存，务必设置
a.click();
```

**拦截不到的写法（必须改用第四节方案）**：

| 写法 | 是否支持 |
|------|---------|
| `a.click()`（`a.href` 为 blob:） | ✅ 自动拦截 |
| 用户直接点 `<a href="blob:..." download>` | ✅ 自动拦截 |
| `location.href = blobUrl` | ❌ 拦截不到 |
| `window.open(blobUrl)` | ❌ 拦截不到 |

**大小限制**：blob 方式单文件上限约 **10MB**（转 base64 后约 14MB 消息上限）；超限或用 `location.href = blobUrl` 的，请改走第四节的原生直下，无大小限制。

## 六、接收下载结果（可选）

App 端下载完成后，会把结果通过 `evaluateJavascript` 回传给 H5。页面实现以下全局函数即可收到：

```javascript
window.onDownloadResult = function (data) {
  // data = { success, url, filename, path, message }
  if (data && data.success) {
    console.log('下载成功:', data.filename, '→', data.path);
    // 可自行 toast / 跳转 / 刷新列表
  } else {
    console.error('下载失败:', (data && data.message) || '');
  }
};
```

| 字段 | 说明 |
|------|------|
| `success` | `true` / `false` |
| `url` | 下载地址（blob 方式此字段为空） |
| `filename` | 实际保存的文件名（重名时为 `账单(1).html` 这种自动编号后的名字） |
| `path` | 完整保存路径，如 `/storage/emulated/0/Download/账单.html` |
| `message` | 结果描述 / 失败原因 |

> 注意：未实现该函数时 App 端静默，不会报错；下载中 App 端始终有系统级 Toast 提示。

## 七、完整可复制示例

把以下代码直接放进页面，按钮绑 `onclick="downloadFile(url, name)"` 即可：

```javascript
/**
 * 通用下载函数：App 内走原生下载，浏览器走自带下载
 * @param {string} url  文件真实地址（http/https）
 * @param {string} [filename] 期望保存的文件名
 */
function downloadFile(url, filename) {
  if (!url) return;

  // App 内：交给原生 DownloadManager
  if (window.UniWebView && typeof window.UniWebView.postMessage === 'function') {
    window.UniWebView.postMessage(JSON.stringify({
      type: 'download',
      data: { url: url, filename: filename || '' }
    }));
    return;
  }

  // 浏览器：blob + download 属性（PC/普通浏览器可用）
  fetch(url)
    .then(function (r) { return r.blob(); })
    .then(function (blob) {
      var a = document.createElement('a');
      a.href = URL.createObjectURL(blob);
      a.download = filename || '';
      document.body.appendChild(a);
      a.click();
      a.remove();
    })
    .catch(function (err) { console.error('下载失败:', err); });
}

// 接收 App 下载结果（可选）
window.onDownloadResult = function (data) {
  if (data && data.success) {
    alert('已下载到手机 Download 目录：' + (data.filename || ''));
  } else {
    alert('下载失败：' + ((data && data.message) || '未知原因'));
  }
};
```

页面按钮示例：

```html
<button onclick="downloadFile(
  'https://foxhisfiles.oss-cn-hangzhou.aliyuncs.com/9999999/SLIM/bill.html',
  '账单.html')">下载账单</button>
```

## 八、保存位置与文件名规则

| 项目 | 规则 |
|------|------|
| 保存目录 | 系统下载文件夹 `/storage/emulated/0/Download/`，文件管理器"下载"分类可见 |
| 重名处理 | 自动追加序号：`账单.html` → `账单(1).html` → `账单(2).html`（与浏览器一致） |
| 文件名来源优先级 | 1. H5 传入的 `filename` / `a.download`；2. 服务器 `Content-Disposition`；3. URL 末段 |
| 非法字符 | 文件名中的 `/ \ : * ? " < > |` 会被替换为 `_` |
| App 卸载 | 公共下载目录中的文件**不会**被删除 |

## 九、注意事项

1. **只在 App WebView 里有效**：普通浏览器里 `window.UniWebView` 不存在，直接调用会报错——务必按第三节先判断环境
2. **URL 必须带协议**：`https://` 开头，纯相对路径（如 `/files/报告.pdf`）原生无法处理，请传拼接好的完整地址
3. **消息大小**：`type:'download'` 消息本身很小无限制问题；blob 方式受 10MB 单文件上限约束
4. **下载进度**：原生无进度回调，文件小（秒级）体验无感；大文件建议 H5 在发起前自行显示"下载中"提示，收到 `onDownloadResult` 后关闭
5. **跨域**：第四节方案不涉及跨域（原生直接下载 OSS 文件）；blob 方案的 `fetch` 需 OSS 允许跨域或页面与文件同源
6. **调试**：App 内可用 vConsole 查看发送的消息与错误日志

## 十、常见问题 FAQ

**Q1：点了下载没反应？**
先确认 App 是否装了新版基座（旧包无下载能力）；再用 vConsole 确认 `window.UniWebView` 存在、消息已发出。

**Q2：blob 下载在 App 里还是没反应？**
检查是否用了 `location.href = blobUrl` 或 `window.open(blobUrl)`（拦截不到），改成 `a.href = blobUrl; a.download='xxx'; a.click()` 或直接换第四节方案。

**Q3：下载的文件名不对？**
确认传了 `filename`（或 `<a download="xxx">` 属性）；不传时按 URL 末段命名，URL 带 query 参数时插件会自动去掉。

**Q4：能下载 PDF / 图片 / zip 吗？**
能。原生下载不限文件类型，同样保存到 Download 目录。

**Q5：OSS 链接带签名参数（鉴权）能用吗？**
能。原生按你传的完整 URL（含签名 query）下载，签名在有效期内即可。
